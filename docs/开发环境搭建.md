# 开发环境搭建

> 本文记录了实际搭建过程中踩到的全部坑。**请按顺序执行**，跳步大概率报错。

## 一、版本要求（不要随意升级）

| 组件 | 版本 | 为什么锁这个版本 |
|---|---|---|
| JDK | **8**（8u451 或更新的 8.x） | 项目 `pom.xml` 里 `java.version=1.8`。**不要用 JDK 11/17**，SpringBoot 2.2.2 不兼容 |
| Maven | 3.9.x | 3.9.16 实测可用 |
| Node.js | **16.x** | 见下方「为什么必须是 Node 16」 |
| MySQL | 8.0 / 9.x | 项目原本面向 5.7，8.0 以上实测可用 |

### 为什么必须是 Node 16

- **Node 18+ 会崩**：项目是 vue-cli 4 + webpack 4，webpack 4 用了 OpenSSL 3 已废弃的哈希算法，
  Node 17 起会报 `ERR_OSSL_EVP_UNSUPPORTED`。虽然能用 `NODE_OPTIONS=--openssl-legacy-provider`
  绕过，但每个人每次都要设环境变量，不如直接锁 Node 16。
- **Node 14 及以下也不行**：原项目依赖 `node-sass@4.13`，它只支持到 Node 13。

## 二、JDK 注意事项

如果你机器上装了多个 JDK，确认 `JAVA_HOME` 指向的是**较新的 JDK 8**：

```
java -version          # 看运行时版本
mvn -v                 # 看 Maven 实际用的是哪个 JDK
```

⚠️ **老版本 JDK 8（如 8u45、8u101 这类 2015-2016 年的）会导致 Maven 下载依赖时
TLS 握手失败**，因为它们不支持现代 TLS 证书链。如果 `mvn -v` 显示的版本很老，
把 `JAVA_HOME` 改成新的 JDK 8 目录。

## 三、Maven 配置（国内网络必看）

在 `C:\Users\<你的用户名>\.m2\settings.xml` 创建配置。

**如果你在用代理软件（Clash / v2ray 等）**：Java **不读** `HTTP_PROXY` 环境变量，
必须在 `settings.xml` 里显式配置，否则一直报
`Remote host terminated the handshake / SSL peer shut down incorrectly`：

```xml
<settings>
  <proxies>
    <proxy>
      <id>local-http</id><active>true</active><protocol>http</protocol>
      <host>127.0.0.1</host><port>7897</port>
      <nonProxyHosts>localhost|127.0.0.1|*.local</nonProxyHosts>
    </proxy>
    <proxy>
      <id>local-https</id><active>true</active><protocol>https</protocol>
      <host>127.0.0.1</host><port>7897</port>
      <nonProxyHosts>localhost|127.0.0.1|*.local</nonProxyHosts>
    </proxy>
  </proxies>
</settings>
```

端口 `7897` 换成你自己代理软件的端口。

**如果你不用代理**：改用阿里云镜像会快很多：

```xml
<settings>
  <mirrors>
    <mirror>
      <id>aliyun</id><mirrorOf>central</mirrorOf>
      <url>https://maven.aliyun.com/repository/public</url>
    </mirror>
  </mirrors>
</settings>
```

> ⚠️ 两者不要同时用。实测「开着代理 + 阿里云镜像」会握手失败，因为代理把
> 阿里云的流量绕到了国外。**开代理就走中央仓库，不开代理就走阿里云。**

## 四、数据库

```
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS t040 DEFAULT CHARSET utf8mb4;"
mysql -u root -p t040 < db/T040.sql
```

共 13 张表。导入后修改 `back/src/main/resources/application.yml` 里的
`spring.datasource.password` 为你自己的 MySQL 密码。

> ⚠️ **不要把你的真实密码提交到 git**。本地改完后用
> `git update-index --skip-worktree back/src/main/resources/application.yml`
> 让 git 忽略你的本地修改。接大模型 API 时，Key 一律放 `.env`（已在 `.gitignore` 中排除）。

## 五、后端

```
cd back
mvn clean package -DskipTests
java -jar target/t040-0.0.1-SNAPSHOT.jar
```

启动后接口地址：`http://localhost:8080/springboot93c4v`
（注意有 `context-path`，直接访问 `localhost:8080` 是 404，这不是报错）

## 六、前端

```
cd front
npm install
npm run serve
```

访问 `http://localhost:8081`。

### 已经处理过的三个坑（了解即可，无需再操作）

1. **`node-sass` 已替换为 `sass`（dart-sass）**
   原项目用 `node-sass@4.13`，需要本地编译 C++ 原生模块，在 Node 16 上装不上。
   已改为纯 JS 实现的 `sass@~1.32.13`，配合 `sass-loader@8` 正常工作，`.scss` 语法无需改动。

2. **95 处 `/deep/` 已替换为 `::v-deep`**
   dart-sass 比 node-sass 严格，Vue 2 早期的深度选择器写法 `& /deep/ .el-button` 会直接报
   `SassError: expected selector`，构建失败。已全量替换为 Vue 2 官方推荐的 `::v-deep`，
   样式效果完全一致。**以后写深度选择器一律用 `::v-deep`，不要再用 `/deep/` 或 `>>>`。**

3. **原 `package-lock.json` 已删除**
   上游那份锁文件把 1195 个依赖地址全锁死在 `registry.npm.taobao.org`——
   这个源 2022 年已停用、域名不解析，会导致 `npm install` 报 `ECONNRESET`。
   现在用的是重新生成的锁文件。**如果你 clone 下来 install 报 taobao 相关的网络错误，
   说明拿到了旧锁文件，删掉 `package-lock.json` 和 `node_modules` 重装即可。**
