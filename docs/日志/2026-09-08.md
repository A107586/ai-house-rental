原先 174 条全是界面描述——「参照图N，图标M，静态显示什么、点了怎样」。

每条写明触发条件、计算口径、边界与异常，**可直接当验收用例读**，
不出现「合理处理」「正常显示」这类没法验收的话。规则全部从代码里读出来，
比如押金取值的四级优先级、缴费三段式的关单逻辑、佣金基数取合同月租的理由。

### 第二次：只写成功，没写失败

评审举的例子是登录按钮那条：

> 动作：点击后校验用户名与密码非空，调用登录接口，**成功则**保存令牌
> 并关闭对话框、刷新页面身份

失败怎么办没写，验收时无从判断对错。

分三批扫完全表，**改了 152 条**（界面条目的 87%），按四类补：

| 类型 | 补什么 |
|---|---|
| 校验失败 | 输入不合法时提示什么、是否阻断提交 |
| 业务失败 | 后端拒绝的具体原因与文案 |
| 系统失败 | 网络、超时、服务不可用时的降级行为 |
| 空态与边界 | 无数据、为零、分母为零、超长、重复点击时显示什么 |

几条是补的时候才想清楚的：

- **出租率卡片**：房源总数为 0 时显示「—」不是「0%」——**分母为零不是
  「出租率为零」**
- **工单总览**：无工单时 SLA 达成率显示「—」不是 100%——没有样本不等于全部达标
- **房东信息卡**：新房东显示「暂无」不是 0——「已出租 0 套」和「新房东」
  给用户的印象完全不同

- **电梯字段**：缺失时显示「—」不默认为「无」——默认成「无」等于替房东

## 四、踩的坑

### 1. 我测出了假数据，而且差点信了它

给全部 20 个动作做路由命中率实测，头一轮结果是「接上模型提升 +0」。
按理说接上模型应该有提升，没有就说明模型没用——差一点就下这个结论。

查下去发现**每一次调用都失败了**：中转站把 `gpt-5.4-mini` 下线了，
返回 503「无可用渠道」。系统按设计静默退回规则——功能全在、测试全绿、
用户无感，**只是模型根本没参与**。而 `/health` 还写着「大模型 + 规则」。

> **配置上了不等于调得通。** 优雅降级是对的，但它把「模型没接上」
> 这件事一起藏了起来。所以健康检查现在报这个进程里的调用成败，
> 而不只是「配置里有没有填 Key」。

修完之后命中率从 30% 升到 94%——**第一轮那个「+0」是假的**。

### 2. `str(None)` 是 `"None"`，非空

`next_missing` 用 `str(slots.get(...)).strip()` 判空，
而上游拿不到房源上下文时给的正是 `None`。

于是「修改房源」「发起签约」**默默跳过第一问**——用户没被问过是哪一套，
助手却认为问过了，接着拿字符串 `"None"` 当房源编号往下走。
表现很怪：一进来就问「（第 2/3 项）改哪一项」。

> 这是 Python 里的经典坑：`str()` 会把 `None` 变成一个长度为 4 的非空字符串。
> 判空必须显式判 `is None`，不能靠 `str()` 之后再 strip。

### 3. 同一个错误，在自己新写的代码里又犯了三次

K-13 的结论早就写进需求书：**归属按当事方判断，不按角色**。
这次核对发现四处仍在按角色分支，**其中三处是我这两批自己写下的**。

> 写进文档挡不住自己再犯。真正有效的是**定期拿着结论去扫代码**，
> 而不是指望写过一次就不会重蹈。

### 4. 补丁脚本里的百分号撞上格式化

给矩阵补失败分支时，插入的文本里有「不是「0%」」和「不是 100%」，
而那两行字符串本身带 `% DANGER` 格式化：

```
TypeError: not enough arguments for format string
```

`%` 字面量在格式化字符串里必须写成 `%%`。第三批的脚本里加了自动转义。
