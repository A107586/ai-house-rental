## 二、时间线

### 08:47 · 一句话 17.7 秒，降到 3.5 秒 · @A107586

接上中转站之后实测，三句话的耗时是：

```
帮我找中山区两室一厅    7.1 秒 / 2 次调用
帮我把这个月房租交了   17.7 秒 / 2 次调用
押金怎么退         42.1 秒 / 4 次调用
```

根因是**意图分类每一轮都要问一次大模型**。可绝大多数用户输入，规则在
几毫秒内就能百分之百确定意图——「押金怎么退」是问规则，「交房租」是办事，
这类句子不需要模型参与判断。改成规则有把握时直接短路，只在规则含糊时
才付那次往返。

> 这条与 9-02 定下的「融合架构」并不矛盾。融合说的是**结论**要两者共同产出，
> 不是每一个中间步骤都得问一遍模型。分不清这两件事，就会为了架构的整齐
> 付出四十秒的代价。

> 上一轮我把「两个搜索bug」读成了「两个搜索里的 bug」，改了两处毛病却

顺带修掉「桂林街」被当成一个区、结果查出 0 套的问题。

## 三、原型图：三次返工

矩阵的「详细说明」写成「参照图N，图标M」，那就得有一张图，能让评审
照着 M 找到那个元素。这件事换了三种做法：

**第一次：直接截真实界面。** 问题是截出来是一个功能完整、数据饱满的产品，
而这份文档的前提是「尚未开工」——图和文档自相矛盾。

**第二次：手写一套静态原型。** 灰条占位、线框风格。评价是「太简陋」，
改成高保真之后又发现更根本的问题：**另画一套原型，它和实现必然对不上，
而且要维护两份。**

**第三次（采用）：在真实前端上叠一层编号。** 写了一个标注器注入页面，
按 CSS 选择器或文本定位元素，把橙色编号角标绝对定位叠上去；再用无头浏览器
把界面开到该展开的状态（展开地图、展开筛选、点开房源、切进各面板），
注入标注后按内容实际高度截图。

**图与实现天然一致**，不存在另画一套原型必然对不上的问题。

> 这套出图脚本**没有入库**——它是为出这一版图写的一次性工具，
> 依赖 selenium 与本地 Chrome，进了仓库反而要维护。产物（矩阵与图）已入库，
> 下次需要重出图时按本节的做法重写即可。

## 四、踩的坑

### 1. 我照着自己画的原型，写了不存在的界面文案

矩阵里图1 写的是「静态显示"欢迎回来"」「登录后可收藏房源、预约看房、签约与缴费」。
**真实弹窗里没有这两句。** 实际有的是演示账号提示和「注册一个 · 忘记密码」。

来源是第二次返工时我手写的那版原型——原型作废了，照着它写的文字却留在了
文档里。这正是「另画一套原型」的代价，只不过代价落在了文档上而不是代码上。

目前只改了标注脚本的定位表，**矩阵里的文字还没改**，因为得先定
「让实现去对文档，还是让文档去对实现」。

### 2. 变更履历的数字对不上，被断言拦下

履历里每版写「新增 N 项」，累计应当等于功能点总数。第一次跑：

```
AssertionError: 变更履历累计 192 与功能点 174 不一致
```

这个断言是写脚本时顺手加的，结果第一次运行就拦住了一处真实错误。
**文档里的数字同样需要校验**——表格不会因为写在 Excel 里就自动自洽。

### 3. 合并单元格写不进去

给「担当者」表头加副标题时：

```
AttributeError: 'MergedCell' object attribute 'value' is read-only
```

J4:J5 是合并区，只能写锚点 J4。这条在 skill 文档里写着，我没照做。

### 4. 补丁脚本里的嵌套三引号

用 heredoc 打补丁时，补丁内容里含 Python 文档字符串，把外层的字符串提前
截断了，脚本静默没更新——但**构建照常成功、照常打印"已保存"**，
用的是旧素材。

> 这是 9-03 那条教训的同一类：**验证手段本身也会错。** 上次是核查脚本报
> 「接口一个都没注册」，这次是打补丁的脚本假装成功了。
