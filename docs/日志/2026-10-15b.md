## 二、基线暴露的问题与改法

多数问题不是模型笨，是**交给它的东西不全或是错的**：

| 现象 | 根因 | 改法 |
|---|---|---|
| 说不出哪套有电梯、近学校 | 房源字段按顺序截前 12 个，电梯、配套、评分排在第 13 位之后 | 房源按名字挑字段（`_house_row`） |
| 「第二套离公司远吗」答「没写明距离」 | 讲单套房时工具里又问一次模型，内层只看得到这一句，不知道公司在星海广场 | agent 调用时把房源资料整份交回，不再二次问模型 |
| 回答里的「第 2 套」和屏幕上的第 2 套不是同一套 | 模型自己重排了编号 | 提示词：序号以屏幕为准，重排要带原序号 |
| 「甘井子和金州都行」只显示金州的结果 | 一轮两次找房，前端只留最后一次 | 同一轮的找房结果合并上屏，序号接着数 |
| 「是不是把没到期的也算进去了」答「可能」/「未到期 0 笔」 | 账单卡片只带前 5 条，汇总拿这 5 条算 | 列表截断时不算合计；逾期 / 未到期由手里有全量的 runner 算 |
| 对房东说「林小雨欠 39650 元」 | `unpaid_total` 含未到期账单 | 后端补 `overdue_total`，易误读字段给中文解释 |
| 「挂了很久」判断不了 | 房源接口没给上架日期 | `to_dict` 补 `published_at`，观察里带状态、上架日期、浏览量 |
| 未登录约看房答「没有预约入口，去 App 约」 | 写工具对未登录用户整个隐藏 | 模型要了隐藏工具时说明「要先登录」 |
| 漏水先用文字问「要不要帮你报修」，话题一岔就落下 | — | 提示词：卡片本身就是征求同意 |
| 报修追问「要拍照吗」时问「一般多久能修」，问题被吞、卡片直接出来 | 「一般」以「一」开头，被当成选了第一个选项 | 光秃秃的数字后面只认量词或标点 |
| 复述截成「……房东消息也不回，处。」 | `content[:30]` | 在分句处断开 |
| 「降到市场价约 4800」没认出数 | 正则要求数字紧跟「降到」 | 允许中间夹几个字 |
| 「那套续一年」又问「续哪一份」 | 自己租的房一律丢掉模型给的编号 | 是他在租的那套就留着 |
| 两个规则问题拼一句查知识库，被判没依据 | — | knowledge 一次只问一件事 |
| 找「差不多但大一点」查回合租单间 | 找房工具没有出租方式参数 | 加 `rent_type` |
| 「第一套和我刚才看的比」说成 123 平对 121 平 | 对比表被截成 80 个字，模型拿屏幕上另一套补 | 对比表按房源列全 |
| 在租 3 套，报修直接挂到第一套 | 报修取第一份生效租约 | 多套时问是哪一套 |
| 自称「通义千问」、回答里出现 `**` | — | 提示词 + 去掉加粗记号 |

## 三、识图

模型换成带识图的启动方式（`start-ninfer.ps1 -Vision`）。测试图：四张真实损坏照片来自
Wikimedia Commons（天花板水渍、滴水龙头、卫生间发霉、墙面裂缝，CC 授权，只在本地临时目录）；
电费单、合同条款、别家平台房源三张截图是本地网页渲染的，数据虚构；干净房间用项目自带的房源图。

| 场景 | 第一遍 | 改后 |
|---|---|---|
| 天花板水渍「变成这样了」 | 认出水渍霉斑、出报修；先问在租 3 套里是哪一套 | 同左 |
| 只发一张滴水龙头、不说话 | 认出「水龙头一直滴水」，走报修 | 同左 |
| 发霉「要紧吗、对身体有影响吗」 | 直接出报修追问，**问题没人答** | 写工具带 say：先答问题，追问接在后面；say 里「我帮你提交了报修」这类话由代码删掉（卡片还没确认） |
| 墙面裂缝「需要报修吗」 | 认出裂缝与踢脚线翘起；复述成「……脱落，需要。」 | 「需要报修」整个摘掉；say 先答 |
| 干净房间「有什么要报修的吗」 | 说没有明显问题，不派单 | 同左 |
| 电费单「谁交、交多少」 | 读出 93 元、10-25 截止，查规则答租客自交 | 同左 |
| 合同三条「合理吗」 | 押金三个月偏高、维修全归租客偏严都对；「押金不退 + 另付违约金」说成「和平台规则方向一致」 | 接上 AI-02 合同审阅（`review_contract`），标出押金不退为高风险 |
| 别家平台截图「有差不多的吗」 | 读出星海广场一室一厅 2800 整租，查到 2 套相近的并说明哪套最接近 | 同左 |

识图本身没出错：四张损坏照片都说对了位置和现象，干净房间没有误报；墙面裂缝那张本来就淡，
复测有一次模型说「照片有点模糊」、请用户确认——看不清就照实说，这是对的。问题都出在
「看懂之后怎么办」——问题被写工具截断、复述被截坏、手边缺一个合同审阅工具。

## 四、踩的坑

**提示词挡不住的，交给代码。** 让模型在 say 里先答问题之后，它两次写了「我帮你提交了报修，
你点确认就行」，紧接着就是「你在租的有 3 套，是哪一套？」。提示词第 4 条早就写着
「绝不能说已经帮你办好了」，加了一句专门针对 say 的也没用。这是安全边界，
改成在代码里删掉这类句子（`loop._drop_done_claims`）。
