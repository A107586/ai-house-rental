### 15:21–15:51 · 智能体骨架与前两个 AI 需求

- 智能体服务骨架 + **AI-01 自然语言找房**
- **AI-06 智能预约看房**
- 业务后端 + 智能体端到端跑通

架构定的是 **Supervisor 多智能体**：总调度判意图，再路由到子智能体，
每个子智能体只带自己领域的工具。三个理由写进了需求说明书：
单一职责让提示词短而准、可增量交付、每个工具是纯函数因而可脱离大模型单测。

同时定下 **「规则优先、大模型兜底」**——规则先解析，置信度不足才调大模型，
大模型不可用就用规则结果。这条让整套系统在没有 API Key 的机器上也能跑，
也是后来全部自动化测试的运行前提。

> 这个二选一的设计在 9-02 晚上被改成了「融合」——两者同时参与，
> 规则的结论作为参考交给大模型。见 [9-02 日志](2026-09-02.md)。

### 16:35 · 补全缺失模块

鉴权、收藏、报修智能体、React 前端。

鉴权用的是 **HMAC 签名的无状态令牌**，不引 JWT 库——签名算法用标准库
`hmac` + `hashlib`，逻辑不到五十行，答辩时讲得清楚。

### 20:41 · 让「访问 8080 就是网站」

原先前端要单独起开发服务器，组员照着文档访问 8080 只看到一句
`{"detail":"Not Found"}`。改成**业务后端直接托管前端构建产物**：
跑过 `npm run build` 之后，8080 就是完整网站。

这里踩了一个顺序坑：`StaticFiles` 挂载到 `/` 会接管所有未匹配路径，
**必须放在文件最末尾**，否则 `/api/*` 请求会被静态文件处理器吞掉。
同理，根路径的 JSON 提示路由只在没有构建产物时才注册——显式路由优先级
高于挂载，无条件注册会把首页整个盖住。

### 22:13 · 交易链打通

签约 → 账单 → 缴费 → 退租。这是整个系统的主干。

几个当时定下、后来一直没改的规则：

- **合同生效时一次性排出整个租期的账单**（1 条押金 + N 条租金），
  而不是每月生成——不然「这份租约总共要交多少」得靠人算
- **退租只作废未到期的租金账单**，已缴的保留
- 押金结算的扣款不能超过押金、不能为负

## 三、两个当天定下的技术判断

### 1. 本地用 SQLite，部署换 MySQL

组员拉下代码就能跑，零安装、无密码。切换只改一个 `DATABASE_URL` 环境变量，
业务代码不动。

代价在 9-03 显现：SQLite 是库级写锁，**预约并发的行级锁在它上面是空操作**，
只有 MySQL 才真正生效。这是这个选择需要付出的代价之一。

### 2. 金额一律 `Numeric(10,2)`，表间用真外键

对照的原型系统里租价字段类型不一致（有的 `int`、有的 `varchar`），
表间全靠业务编号字符串弱关联。这两条写成了需求 R-03 与 R-04，
从第一天就按这个建表，没有留到后面再改。
