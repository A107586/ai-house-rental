### 合同生命周期 · Claude Code

全仓搜 `status = "cancelled"`，合同一处都没有——而 `Contract` 的状态图画着「pending ──任一方取消──► cancelled」，
改条款接口的注释也说「换人签就取消这份重开一份」。复现（`tests/test_contract_lifecycle.py` 的前身）：

```
[1] B after A activated: pending
[1] B activate: 409 该房源已被占用
[1] revert-to-tenant: 400 退回租客前需要先处理：1 份合同尚未结束。下架房源、结清合同之后再来即可。
```

同一套房发给两位租客，A 确认后 B 永远「待确认」、确认又 409；A 退租、房源都下架之后，房东仍然退不回租客——
卡住他的就是 B，而 B 没有任何办法处理掉。

- **拒签 / 撤回**：`leasing.cancel_contract` + `POST /api/contracts/{no}/cancel`，租客点是拒签、房东点是撤回，通知另一方；
  只收待确认的。合同卡片上租客多一个「拒签」、房东多一个「撤回」，都先 `window.confirm`。
- **一份生效，同房其余待确认的自动取消**，通知那几位租客「这套房已与其他租客签约」（同 10-22 委托那条的处理）。
- **同一租客同一套房只留一份待确认**：连点两下「发起签约」原先就是两份。被否决的方案：一套房只许一份待确认——
  房东同时给两个人发合同、谁先确认算谁，是真实存在的做法，拦掉它比让它跑通更糟。

### 确认签约时的两道检查 · Claude Code

- **起租日**：`check_start_date`（最多往前补 30 天）只在发起和修改时查。合同放两个月再确认，起租日就在九十天前：

  ```
  [2] activate: 200 overdue bills: 4
  ```

  一生效就是 4 期逾期——正是这条规矩注释里写的那种情况。确认时再查一遍，过了就 409，请房东改起租日。
- **条款指纹**：待确认合同房东随时能改。租客读着旧条款、房东把月租改高，租客点下的「确认」原先照样生效。
  合同带 `terms_digest`（月租、押金、付款周期、起止日、正文的 SHA-1 前 16 位），页面确认时带上，对不上回 409 要他重看；
  **不带就不比**，智能助手和老页面不受影响。金额先转 float——刚写进会话是 `Decimal("2800")`、读回来是 `Decimal("2800.00")`，
  不转的话同一份条款两个指纹（`test_digest_is_stable_across_reads` 盯着）。

### 私信门槛 · Claude Code

合进来的分支让「签过约、报过修」的人也能被房东主动联系，并跳过免打扰。可「签过约」认的是**任何一份合同**，
而发起签约的租客用户名是手填的：

```
before contract: 403 只能联系在这套房上约过看房、被带看过、签过约或报过修的租客
pending contract: 200
after pending contract (DND on): 200 None
```

给任意用户名发一份待确认合同，就能私信他，免打扰也拦不住——`start_conversation` 注释里要防的「站内群发入口」又开了。
改成：建立往来只认**生效过**的租约（active / ended）与报修；免打扰只对**眼下**的住户让路（租约生效中，或有没修完的工单）。
搬走的前租客设了免打扰，房东不再能凭旧合同一直找到他。`test_repair_contact.py` 里在住租客那两条照样通过。

## 四、踩的坑

**改了的那条用例原先断言的就是错的行为。**（文档与实现不一致）
`test_leasing.TestEndContract.test_deposit_refund` 从没交过押金，却断言 `contract.deposit_refund == 2300`；
而 `Contract` 的说明写的是「`deposit_refund` 记录退租时**实际退还**的押金」。改成先交押金再退，另加一条没交的断言为空。

**出图在容器里跑不起来：`渲染 system 失败：浏览器没有产出截图`。**（环境相关）
`gen_diagrams.py` 给 mermaid-cli 的 puppeteer 配置里有 `--no-sandbox`，但系统结构图那一张是直接起浏览器截图，命令里没有；
root 下的 Chromium 不带它就起不来。没改脚本，用一个转发加 `--no-sandbox` 的包装脚本当 `PUPPETEER_EXECUTABLE_PATH`。
`npm install` 会在 `scripts/` 下生成 `package-lock.json`，仓库里没有这个文件，用完删掉。

**`jieba` 在 Python 3.13 上用系统 setuptools 装不上**（`Failed building wheel for jieba`），而且 `pip install -r a.txt -r b.txt`
一个失败整批都不装，后端测试因此先报了 39 个 ERROR。`pip install --use-pep517 jieba` 能装。CI 是 3.12，不受影响。

**《概要设计》表 3-7 有三行停在旧行为上。** 缴费还写「一条账单一条流水」、退租写「已缴的不动」、
续租写「结束旧合同、生成待确认新合同」——都是 10-22 改掉的。模块结构图就是从这张表生成的，一起改正并重新出图。

## 五、需要拍板的

1. **签约时房东可以单方面改中介佣金比例，改成 0 也行。** 中介只收到一条「有异议请在合同生效前联系房东」，没有任何办法拦。
   付钱的一方单方面定自己欠多少。建议：比例低于委托时的，要中介确认（或至少不允许低于委托比例）。
2. **退租后「住过期间没交的租金」在系统里永远关不掉。** 合同结束后 `_guard_payable` 拒收任何缴费（含管理员代收），
   房东也没有「已线下收到」的入口——线下结清了，租客的「待缴」和房东的「待收」也一直挂着。
   建议：给房东一个「已线下收款」（只对已结束合同的欠款，留流水、通知租客）。
3. **工单状态没有状态机。** `PATCH /api/repairs/{id}` 能把「已完成」改回「待处理」；登记过维修记录的工单再改回去，
   「完成并登记」会 409「已登记过」。页面上没有这条路，只有直接调接口或助手能走到。
