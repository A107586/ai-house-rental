### 11:40 · 两个只在「非交互」下才现形的问题 · @A107586

**一、输出重定向到文件时，打印中文直接把脚本打断。**

Windows 上 Python 按「输出连到了哪里」挑编码：连终端用终端的，
重定向到文件或管道就用本地编码（本机 cp1252，写不出汉字）。

```
$ python -c "print('中文')" > out.txt
UnicodeEncodeError: 'charmap' codec can't encode characters in position 0-3
```

终端里永远复现不出来，而 CI、`start-all.ps1` 里的日志重定向、`| tee`
走的都是那条路。实测影响：

    python -m unittest > out.txt   智能体套件 7 条验收用例报
                                   UnicodeEncodeError，看上去像 7 条挂了，
                                   其实一条没挂

`seed.py` 这类会写库的脚本尤其麻烦——**不是启动时失败，是干到一半才失败**，
留下一个填了一半的数据库。服务端的中文慢请求日志一旦被重定向，
那行日志会变成一段 `--- Logging error ---`（logging 吞了异常，
服务不挂，只是诊断没了）。

新增 `server/app/console.py` 统一处理，原委写在那里。

**二、AI-06 的指标跟着星期几变。**

两条「这周六」用例的期望值没跟着解析器的顺延规则算。解析器对星期表达
有一条规则：「这周六上午九点」在周六上午十点说，指下周六。期望值这边
不顺延，用例就变成**只在周六某个钟点之后才错**——今天恰好是周六，
AI-06 从 100% 掉到 95%，而代码一行没动。

**比红更糟的是它不会红**：两条全错也刚好压在 90% 的线上。
那张验收表上的数字跟着星期几变，谁也说不清哪个才是真的。

验证：按 7 天 × 7 个钟点共 98 次比对，改后零不一致。

### 12:22 · 智能体：52 条客服问题里 17 条端到端答不上来 · @A107586

**先量，再改。** 把智能体当用户用了一遍，一问一答记下来：

```
〉还有别的吗
  （延续上文：沙河口区、两室、租金 3000 元以内）为你找到 3 套……
  total=3 page=1 返回 3 套 ['DL0044','DL0045','DL0047']   ← 和刚才一模一样
```

顺着这条往下查，一共三类问题：

**一、「还有别的吗」把刚才那三套原样又端了一遍。**
页码按 `seen // PAGE_SIZE + 1` 算，上一批 3 套、一页 10 套，算出来还是
第 1 页，于是重搜一次、重印一次「为你找到 3 套」——用户分不清这是新的
还是刚才那批。上一批不满一页就说明已经到底，直接说「没有更多了」。

**二、最自然的几种找房说法，系统回「这个我没查到相关规定」。**

```
中山区的房子      意图=unknown  条件={'suozaidiqu': '中山区'}
沙河口区有什么房    意图=unknown  条件={'suozaidiqu': '沙河口区'}
有电梯的房子      意图=unknown  特征=['电梯']
三千以内的房子     意图=unknown  条件={'zujia_max': 3000}
```

解析器**明明解析出了条件**，意图分类器却说 unknown。原先的救场规则
卡在「两个字段」，这些各只有一个，一路掉到客服兜底。
补一条：一个条件 + 一个「房」字头的名词（或「找个」「想租」这类说法），
就是在找房。语料里 48 个客服问题逐条验过，一条都没被抢走。

**三、问规矩的话被办事流程截走了。**

词表见到「预约」「看房」「报修」就往办事流程送：

    预约了怎么取消    → 「没听清你想什么时候看房」
    报修要不要拍照    → 一条「其他 / 一般」的故障单

判据不靠猜：**办事流程自己说接不了**（预约一个时间也没解析出来、
报修归不了类），**而且这句话确实是个问句**，才转去检索。

问句这道闸是必须的——中间试过不加，结果「我想租房」也解析不出条件，
被转去检索，换回来一条风马牛不相及的规定：

    〉我想租房
      任一方提前解除合同的，应提前 30 日书面通知对方，
      并向对方支付相当于一个月租金的违约金。

**这个中间态比原来更糟**，所以加了问句判据。同一段还暴露出闸门对
没有实质内容的短句偏松（「怎么办」两个词就能把覆盖率顶到 1.0，
换回一条改密码的 FAQ）——那是闸门本身的毛病，记在「留给明天的」。

顺带三处：「没听懂你的找房需求」改成反问「哪个区、几室、预算多少」
（**听懂的是意图，缺的是条件，说没听懂是冤枉他**）；
「你好」原先回「这个我没查到相关规定」，现在整句寒暄回一句寒暄。

| 房源列表 | 1947ms | **305ms** |

| 房源详情 | 666ms | **341ms** |
| 全量聚合 | 455ms | **216ms** |

《需求分析说明书》9.1 原先写「真正的解法是多 worker」，那是推断；
现在是实测，已补进去。

**压测顺手照出一个正确性问题：** 详情接口的浏览量是
`house.view_count += 1`，读-改-写。

```

```

教训：**声称「做不到」之前，先把那条路真的走一遍。**
探测脚本的深度、超时、过滤条件都会骗人，而「检测工具本身出错」
会让人去修根本不存在的问题。


### 四、seed 改一行，随机序列就整体平移

给两份历史合同补上「结束前先结清」之后，历史租约从 106 份变成 104 份。
不是逻辑错——`leasing.pay_bill` 会生成流水号，流水号取随机数，
于是**后面所有 `random` 的消费整体平移**，`_seed_history` 里那次
`shuffle` 洗出来的顺序就变了。

同一版 `seed.py` 仍然完全可复现（连跑两次结果一致），
但**跨版本对不上**。演示库的 `manifest.json` 记了生成时 `seed.py`
的哈希，正是为了这种情况——哈希对不上就说明该重做快照了。

### 五、`_seed_support_logs` 排在 `seed_faqs` 前面，白铺了一轮

第一次铺完客服日志，`被引用过的条目: 0`。原因是我把调用加在了
「铺历史租住记录」后面，而 `seed_faqs(session)` 在更后面——
日志要引用的知识条目那时候还不存在，`codes` 是空字典，
`cited` 写不出来、`hit_count` 也加不上。

现象是「代码看起来全对，数据就是不出来」。挪到 `seed_faqs` 之后即可，
并在调用处写明了顺序约束。

### 六、heredoc 又吃了一次转义

`"\x7f"` 写在 shell heredoc 里，落到文件里成了一个**真的 DEL 控制字符**。
代码功能正确（比较的确实是 DEL），但源码里看不见，改成 `chr(0x7f)`。

昨天记过一次同样的教训（`\n` 被吃掉五次），**今天又踩了**。
判据再明确一点：**正文里只要出现反斜杠，就别走 heredoc。**

## 六、留给明天的

- [ ] **闸门对没有实质内容的短句偏松**。今天量到的：

      随便看看 → cover 0.511 → 「不可以。」
      怎么办   → cover 1.000 → 「登录状态下在账号设置里可以直接修改密码。」
      还有别的吗 → key_hit=True → 「注册时选择身份：租客可以找房……」
