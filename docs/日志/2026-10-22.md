### 缴费与押金 · @A107586（`093ccb5`）

- **收银台过期后，这张账单再也付不了。** 复现：发起支付 → 把支付单改成已过期 → 再发起，
  回 `409 该账单正在支付或已经支付，请勿重复提交`；线下代收也一样。
  根因：`payments.bill_id` 是唯一的，关单只改了状态，重新发起时又插一条，撞唯一约束。
  `start_payment` 里的注释写着「不关的话它会一直占着 bill_id 的唯一约束」——**作者以为关单就让出了约束，其实没有**。
  修法：一张账单一条支付记录，记最近一次尝试；关掉的、失败的就地换成新的一单（新 trade_no），
  旧单迟到的回调查不到它、不会误入账。**不动表结构**——黑盒测试周不做迁移。
  被否决的方案：去掉唯一约束、允许多条支付记录。更「对」，但要迁移、要改 `bill.payment` 的所有用法。
- **退租后没交的押金挂在「待缴」里。** 页面提示「这笔欠款请与房东线下结清」，而退租结算写的是
  「押金未曾缴纳，无需退款」——让人去线下补交一笔租约已结束的押金。押金是担保，不是欠款，现在退租时一并作废。
  **已到期未缴的租金照旧保留**：那是住过的月份，是真欠款。
- 助手「帮我交房租」不看 `payable`：旧租约的欠款到期最早、后端拒收，却排在第一位。现在只挑能付的；
  只剩这种欠款时如实说「要线下结清」，不再说「都结清了」。

   后端 `POST /api/repairs` 也不校验是不是这套房的租客；而房源的维修历史是公开的——等于谁都能往别人的房源页上写

5. **租约过了到期日不会自动结束。** 状态一直「生效中，剩余 0 天」，房源一直「已出租」，要房东手动退租。

## 八、下半夜踩的坑

**另一个会话同时在改同一个工作区。** 05:00 前后 `web/src/App.jsx`、`ChatPanel.jsx`、`styles.css`、`theme.css`
多了别人未提交的动画改动（`useMotion.js`）。处理办法：只 `git add` 自己的文件；`App.jsx` 两边都改了，
就把「HEAD + 我的改动」单独生成出来，用 `git hash-object -w` + `git update-index --cacheinfo` 直接放进暂存区，
工作区里别人的三处改动原样不动。提交前核对暂存区里没有对方的任何一行。

**代码量统计会把别人没提交的文件算进去。** `gen_test_counts.py` 数的是工作区，《技术架构说明》里前端行数
因此包含对方的未提交改动——提交上去，CI 的 `--check` 就会在我的提交上红。每次提交前按「我要提交的那棵树」
重算这一个数（对方改过的文件按 HEAD 版本算、对方的新文件不算）。

**测试从 65 秒变成 210 秒，不是代码变慢。** 同步依赖时装上了 `httpx2`，starlette 的 TestClient 随之改用它，
在 Windows 上每个请求都新起一个事件循环（`socketpair` 那几次 connect 就是它）。试过复用 portal，没用；
CPU 时间只有 3 秒，其余是等。没再深挖，记在这里。
