### 下午 · `gen_diagrams.py`：从代码生成全部的图 · @A107586

| 图 | 从哪读 |
|---|---|
| E-R 图（总览 + 全图） | 模型元数据的外键；端点符号按「可空 / 唯一」决定 |
| 业务后端 9 张模块类图 | 模型类（主键、外键、唯一键、状态列、方法、派生属性）；路由表（处理函数、请求 DTO）；**处理函数的语法树**：它实际调用了哪个服务模块的哪个函数 |
| 智能体 2 张类图 | `agent/app` 的语法树：类、继承、`self.x = Cls(...)` 组合、各子智能体的 `run()` 与工具模块、import 关系 |
| 系统结构图 | 接口数、表数、外键数、子智能体数、工具数，现数 |

类图里服务模块的写法是这一版最费斟酌的地方：`deps`、`permissions` 这种
横切模块九个模块都在用，每张图都列全就是九份一样的清单。
所以定了「主场」——在主场的图里列全部公开函数，在别的模块的图里
**只列那个模块真正调到的函数**，并在构造型上标出「· 账号与权限」。
这些是语法树里解析出来的真实调用，不是按名字猜的：名字先到处理函数的
全局命名空间里查，查到的是 `app.leasing` 模块或其中定义的函数才算数。

渲染用 mermaid-cli，浏览器用本机 Edge（`PUPPETEER_SKIP_DOWNLOAD=1`，不下 Chromium）。
`--check` 不渲染，只比源与 PNG 的指纹，所以测试在任何机器上都能跑。

### 再晚些 · 对照模板逐项核对：模块结构图、类图可读性、版式、日文字体 · @A107586

   补上 10 张模块结构图（模块 → 功能点，每条带说明），**功能点直接读各模块

   7 个服务框竖着叠。改为 HTTP 层只写函数与请求类型、DTO 不单独画框、借用的服务合成一框，
   同一张图降到 2989 × 2910。
3. **版式与模板不一致。** 从模板 .doc 里逐项量出来再照做：页边距（上下 2.0、左 2.5、右 1.5）、

4. **日文字体。** python-docx 自带的底板是日文环境：`settings.xml` 东亚语言 `ja-JP`、
   主题东亚字体「ＭＳ 明朝 / ＭＳ ゴシック」、字体表声明 MS Mincho / MS Gothic。
   标题、目录这些落到主题字体上的文字，在 WPS 里就显示成日文字体。三处都改成中文，

## 四、踩的坑

**1. 手写的 ER 图漏了 14 张表，没有任何人发现。**（文档与实现不一致）
《数据库设计说明书》第二章那张 Mermaid ER 图画了 22 张表，
漏掉 `faqs`、`support_logs`、`support_handoffs`、`conversations`、`chat_lines`、
`notices`、`operation_logs`、`content_flags`、`system_configs`、`role_requests`、
`password_resets`、`refunds`、`saved_searches`、`house_reports`。
那一章的表结构部分早就是生成的、有测试盯着，**唯独这张图是手写的**，
于是模型加了 14 张表，图一张没跟上。现在换成生成，并进了测试。

**2. 类图渲染出来一律 1568 像素宽。**（验证手段本身出错）
`mmdc` 默认视口 800 像素、缩放 2，Mermaid 的 `useMaxWidth` 又默认为真，
所以不管图多大都被压到 1568 宽——房源那张类图字高不到 3 像素。
给 E-R 图和流程图关掉 `useMaxWidth` 就好了，**类图的渲染器却不认这一项**。
最后改成两遍：先出 SVG 读 `viewBox` 的自然尺寸，再按尺寸用 `--size` 出 PNG。

**3. Python 3.14 里 `Union` 也有 `__name__`。**
DTO 的字段类型第一版取 `annotation.__name__`，图上写出一排
`+Union start_date`、`+Literal method`。改用 `typing.get_origin` 拆开。

**4. `from app import fusion` 没被认成 import。**
收集 import 的函数只认 `app.` 开头的模块名，`from app import x` 的模块名
恰好是 `app` 本身，于是子智能体到 `fusion`、HTTP 层到 `supervisor` 的依赖线全没了。
图上看起来 `supervisor` 是个孤岛——**图不会报错，只会悄悄地少一条线。**

**5. 迁移 0016 被挤掉了。**（今天读代码时顺带发现，当时还在工作区里未提交，随 `d5715a4` 修正提交）
新加的 `@step("0017", ...)` 插在了 `@step("0016", ...)` 与它的函数之间：

    @step("0016", "房源表：楼栋与单元（A5）")
    @step("0017", "房源表：审核通过时间，堵住上下架绕过审核")
    def _house_approved_at(...):
    ...
    def _house_building_unit(...):      # ← 没有装饰器了

两个版本号都注册到了 `_house_approved_at` 上，`_house_building_unit`
从迁移列表里消失。已经跑过 0016 的库不受影响；**还没跑过 0016 的旧库
升级后永远不会有 `building` / `unit` 两列**，房源接口会在读这两列时报错。
已把两个装饰器归位，并按版本号排好顺序。

**6. 我的临时脚本叫 `inspect.py`。**（环境相关）
放在工作目录里，把标准库的 `inspect` 顶掉了，numpy 导入时连环报错。改名即好。

**7. 改生成脚本时把它清空了一次。**（验证手段本身出错）
用 Python 一次性替换 `gen_diagrams.py` 里的一大段，`open(..., "w", newline="\\n")`
里的换行参数写错了：**文件先以写方式打开、被截成 0 字节，然后才因参数非法报错**，
新内容一个字都没写进去。靠 Claude Code 的文件快照恢复到截断前那一版，
再用 `--check` 确认它能原样重新生成当时的全部图与文档。之后改大段一律
**先把新内容算好，最后一步才打开文件写**。
