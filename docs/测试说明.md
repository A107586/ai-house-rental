## 一、五分钟跑起来

### 前置条件

只需要 **Python 3.10 或以上**，不需要 MySQL，不需要大模型 API Key。
本地开发用 SQLite，文件就在 `server/rental.db`，零配置。

```
python --version
```

### 第一步：装依赖

```
pip install fastapi uvicorn pydantic sqlalchemy
```

### 第二步：生成演示数据

```
cd server
python seed.py
```

预期输出：

```
用户 13 个（管理员 1、房东 8、租客 4）
房源 108 套，其中可租 101 套
看房预约 15 条
```

数据用固定随机种子生成，**每个人跑出来的结果完全一致**，
因此测试用例里可以写死具体房源编号。

### 第三步：一键启动

在项目根目录执行：

```
powershell -ExecutionPolicy Bypass -File .\start-all.ps1
```

会弹出两个窗口：

| 服务 | 地址 | 接口文档 |
|---|---|---|
| 业务后端 | <http://localhost:8080> | <http://localhost:8080/docs> |
| 智能体服务 | <http://localhost:8000> | <http://localhost:8000/docs> |

也可以手动分别启动：

```
cd server && python -m uvicorn app.main:app --reload --port 8080
cd agent  && python -m uvicorn app.main:app --reload --port 8000
```

## 三、手工测试用例

### 3.1 AI-01 自然语言找房

**不启动任何服务**也能验证解析效果：

```
cd agent
python demo.py
python demo.py "中山区两室一厅，租金三千以内"
```

启动服务后，在 <http://localhost:8000/docs> 里找到 `POST /agent/search` 试用。

| 编号 | 输入 | 预期结果 |
|---|---|---|
| S-01 | 中山区两室一厅，租金三千以内，最好带电梯 | 解析出 `中山区` `两室一厅` `≤3000`，偏好 `电梯`；返回房源且带电梯的排前面 |
| S-02 | 帮我找一个月租3000以内，两室一厅，距离学校近一点，最好有地铁的房子 | 解析出 `两室一厅` `≤3000`，偏好 `地铁`、`近学校` |
| S-03 | 沙河口 合租 单间 1500以下 | 区域补全为 `沙河口区`，户型 `一室`，类型 `合租` |
| S-04 | 甘井子区 80平以上的三室 预算不超过五千 | 面积下限 80，租价上限 5000 |
| S-05 | 有没有金州区2000到3000的一居室 | 识别为**区间**，`zujia_min=2000` 且 `zujia_max=3000`，不能拆成两个上限 |
| S-06 | 中山区两室一厅，租金两千五以内 | 中文口语数字「两千五」解析为 **2500**，不是 2005 |
| S-07 | 旅顺口区三室两厅一千以内 | 查不到结果，且提示**建议把租价上限提高一些** |
| S-08 | 你好啊 | 回复「没听懂你的找房需求」，且**不应发起数据库查询** |

### 3.2 AI-06 智能预约看房

在 <http://localhost:8000/docs> 里找到 `POST /agent/booking`，
请求体需要带 `house_no`（用 `DL0008` 这类真实编号）。

| 编号 | 输入 | 预期结果 |
|---|---|---|
| B-01 | 这周六下午两点 | `status=created`，回复含具体日期时刻 |
| B-02 | 重复提交 B-01 | `status=conflict`，提示已被预约，并给出其它空闲时段 |
| B-03 | 这周六 | `status=need_time`，列出当天可选时段，且**不含已被占用的时段** |
| B-04 | 最近三天都可以 | `status=need_choice`，跨天列出候选时段 |
| B-05 | 这周六晚上十点 | `status=conflict`，提示看房时间为 09:00–18:00 |
| B-06 | 上周一下午两点 | 拒绝，提示时间已过去 |
| B-07 | 我想看房 | `status=need_time`，提示「可以说这周六下午两点」 |
| B-08 | 下周一下午三点半 | 日期是**下周那个周一**，不是两周后 |

> **时间相关用例注意**：`下周一`、`这周六` 的具体日期取决于运行当天是星期几。
> 自动化测试里注入了固定的「现在」（2026-09-01 周二），手工测试时请自行换算。

### 3.5 降级与容错（重点）

这几条对应需求文档 N-07，**答辩时大概率会被问到**，务必验证。

| 编号 | 操作 | 预期结果 |
|---|---|---|
| F-01 | 不配置 `LLM_API_KEY` 启动智能体 | 正常启动；`GET /health` 显示 `mode: 纯规则（降级模式）` |
| F-02 | 降级模式下执行 S-01～S-05 | **全部正常返回结果**，找房功能不依赖大模型 |
| F-03 | 关掉业务后端（8080），再调 `POST /agent/search` | 返回「房源服务暂时不可用，请稍后再试」，**不能抛 500** |

| F-05 | 填一个无效的 `LLM_API_KEY` 后提问一句规则识别不了的话 | 自动回退规则结论，`source` 为 `rules_fallback`，不报错 |
