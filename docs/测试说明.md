## 一、五分钟跑起来

### 前置条件

| 需要 | 说明 |
|---|---|
| Python 3.10+ | 后端与智能体 |
| Node.js **16.x** | 前端。Node 18+ 会因 webpack/OpenSSL 问题报错 |
| MySQL | ❌ **不需要**。本地开发用 SQLite，零配置无密码 |
| 大模型 API Key | ❌ **不需要**。没有 Key 时系统降级为纯规则模式，核心功能全部可用 |

### 第一步：装依赖

```
pip install fastapi uvicorn pydantic sqlalchemy
cd web && npm install
```

### 第二步：生成演示数据

```
cd server
python seed.py
```

预期输出：

```
用户 13 个（管理员 1、房东 8、租客 4）
房源 108 套，其中可租 95 套
看房预约 15 条，报修工单 4 条
租约 6 份，公告 5 条
房源图片 14 张，每套 3 张
```

数据用固定随机种子生成，**每个人跑出来完全一致**，所以用例里可以写死房源编号。

### 第三步：打包前端

```
cd web
npm run build
```

打包一次即可。之后业务后端会直接托管这份产物，
**访问 8080 就是完整网站**，不需要单独启动前端服务。

### 第四步：启动

```
powershell -ExecutionPolicy Bypass -File .\start-all.ps1
```

| 地址 | 说明 |
|---|---|
| **<http://localhost:8080>** | **网站入口，主要测试就在这里** |
| <http://localhost:8080/docs> | 业务后端接口文档 |
| <http://localhost:8000/docs> | 智能体接口文档 |

> **改前端代码时**才需要开发模式：`cd web && npm run dev`，
> 然后用 <http://localhost:5173> 访问，有热更新。
> 两种模式功能完全一致。

### 常见问题

| 现象 | 原因与解法 |
|---|---|
| 访问 8080 只看到 `{"detail":"Not Found"}` | 用的是旧版本代码。拉最新代码，跑一次 `cd web && npm run build` |
| 访问 8080 看到一段 JSON 提示「还没有前端构建产物」 | 没打包。执行 `cd web && npm run build` 后刷新 |
| `npm` 不是内部或外部命令 | 终端是装 Node **之前**开的，PATH 没刷新。**开个新终端**即可；`start-all.ps1` 也会自动去常见位置找 npm |
| 页面能开但搜索报「连不上服务器」 | 智能体服务（8000）没启动 |

### 3.1 AI-01 自然语言找房

首页搜索框输入后点「智能找房」。

| 编号 | 输入 | 预期结果 |
|---|---|---|
| S-01 | 中山区两室一厅，租金三千以内，最好带电梯 | 页面出现绿色标签 `区域：中山区` `户型：两室一厅` `租价 ≤ 3000 元` 和红色标签 `偏好：电梯`；带电梯的房源排前面 |
| S-02 | 帮我找一个月租3000以内，两室一厅，距离学校近一点，最好有地铁的房子 | 解析出 `两室一厅` `≤3000`，偏好 `地铁`、`近学校` |
| S-03 | 沙河口 合租 单间 1500以下 | 区域补全为 `沙河口区`，户型 `一室`，类型 `合租` |
| S-04 | 甘井子区 80平以上的三室 预算不超过五千 | 面积下限 80，租价上限 5000 |
| S-05 | 有没有金州区2000到3000的一居室 | 识别为**区间**，同时出现租价上下限，不能拆成两个上限 |
| S-06 | 中山区两室一厅，租金两千五以内 | 「两千五」解析为 **2500**，不是 2005 |
| S-07 | 旅顺口区三室两厅一千以内 | 结果为空，提示**建议把租价上限提高一些** |
| S-08 | 你好啊 | 提示「没听懂你的找房需求」 |

**每次搜索都要检查标签区括号里的说明**，未配 Key 时应显示「规则解析，未调用大模型」。

### 3.5 AI-02 合同智能审阅

「我的租约」里任一合同 → 点「智能审阅」。

| 编号 | 对象 | 预期结果 |
|---|---|---|
| C-01 | 平台生成的任意合同 | 评分 **≥ 90 且为绿色**，六项条款全部抽出，标注「规则解析，未调用大模型」 |
| C-02 | 同上 | 风险列表只有「禁止转租」这类低风险提示，**不能出现高风险** |
| C-03 | 查看条款卡片 | 租期、租金、押金、付款方式、违约责任、维修责任六项齐全 |
| C-04 | 每条风险 | 都有「依据原文」「问题说明」和深青色的「建议」 |

> **C-02 是重点**：规范合同被报出高风险的话，功能就成了狼来了，
> 用户会直接忽略所有提示。

**造一份坑合同验证召回**（在 <http://localhost:8080/docs> 调
`POST /agent/contract/review`，或直接调智能体的 <http://localhost:8000/docs>）：

正文里包含下列句子，每句对应一条应被识别的风险：

| 句子 | 应识别 | 级别 |
|---|---|---|
| 押金不予退还 | 押金不退条款 | 高 |
| 甲方有权单方面解除本合同 | 房东可单方面解约 | 高 |
| 甲方有权根据市场情况随时调整租金 | 租期内可调整租金 | 高 |
| 房屋内一切维修费用均由乙方承担 | 维修责任全归租客 | 中 |
| 乙方不得提前退租 | 不允许提前退租 | 中 |
| 租赁期满乙方未提出异议的，本合同自动续约一年 | 自动续约条款 | 中 |
| 甲方有权随时进入房屋查看 | 房东可随意进入 | 中 |
| 月租金 3000 元，押金 12000 元 | **押金偏高**（4 倍月租） | 中 |
| 月租金 3000 元，违约金 10000 元 | **违约金过高** | 高 |

最后两条要靠数值比对才能发现，不是关键词匹配——**这两条最能体现智能体的价值**。

### 4.3 会被误当成 bug 的现象

| 现象 | 原因 |
|---|---|
| 房东发布的房源在前台看不到 | **设计如此**，需管理员在「管理后台 → 房源审核」通过后才上架 |
| 房东改完房源后房源消失了 | **设计如此**，修改关键信息会退回待审核，防止先发合规内容过审后再改 |
| 匿名访问 `/api/houses?status=pending` 返回的全是可租房源 | **设计如此**，待审与已下架不对外可见 |
| 匿名访问 `/api/repairs` 返回 401 | **设计如此**，全平台工单含联系人与故障描述，必须登录 |
| 房东看不到别人房源的工单 | **设计如此**，按归属过滤 |
| 租约还在生效时无法评价 | **设计如此**，租约结束后才能评 |
| 管理员改不了自己的账号状态 | **设计如此**，防止一键锁死后台 |
| 智能搜索结果没有「加载更多」 | 已知限制，一次取 50 条 |
