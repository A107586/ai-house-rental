开发过程中修复的越权问题

问题影响修复
匿名可查待审房源房东一发布就被公开看到，审核机制形同虚设非管理员只能查 available 与 rented
工单状态无归属校验任何房东能改别人房源工单，甚至把没修的标成已完成房东只能处理自己房源的工单
工单列表无鉴权匿名可拉全平台工单，含联系人与故障描述不带房源号必须登录且按角色限定范围
预约表的唯一约束取消的预约永久占住时段，与「取消后释放」冲突移除约束，冲突校验交给接口层
管理员可禁用自己一键锁死整个后台拒绝修改自身状态
测试文件各自建内存库后导入的覆盖前者，27 个用例误报共享状态统一到 tests/base.py

07视觉设计

现状问题

问题影响
没有任何图片最致命。租房是看图决策的生意，纯文字卡片说服力极弱
首屏没有主视觉打开就是搜索框加一排卡片，缺少「这是个租房网站」的第一印象
信息层级偏平卡片上租金、户型、标签视觉权重接近，扫视时抓不住重点
缺少空状态与加载态搜索时只有按钮文字变化，没有骨架屏，感觉卡顿
只有一种布局没有列表／网格切换，没有地图视图

深青代表智能体层，砖红代表房屋与租金。翻页面时哪些是智能体的能力、哪些是传统业务一眼可分——答辩时这是个讲得出理由的设计决策，不是审美偏好。本页也在用同一套色板。

字体与间距

  • 中文用系统默认（PingFang SC / Microsoft YaHei），不额外引入中文字体拖慢加载
  • 数字一律 font-variant-numeric: tabular-nums，保证租金在列表里对齐
  • 标题与正文只用两级字重，不要花
  • 间距以 4px 为基准，卡片内边距 16–20px，区块间距 24–32px

三个要点：

  • 图片占卡片上半部，收藏与类型角标浮在图上，不占正文空间
  • 租金是全卡最重的元素——22px、700 字重、砖红色
  • 标签用小圆角灰底，最多显示 4 个，避免喧宾夺主

左侧是本页直接渲染的提议样式，可以直接对照着写 CSS。

其余页面

  • 首页主视觉：用大连真实地标（星海广场、跨海大桥）做背景图，搜索框压在图上，下方一行数据「101 套在租 · 6 个城区 · AI 秒懂你的需求」
  • 房源详情：左右分栏。左侧相册加描述，右侧固定一个「租金 + 预约」卡片，滚动时跟随
  • 工作台与看板：这类页面是信息设计不是排版——数字要大、异常项用语义色标出来，配 ECharts 折线图与饼图

交互细节

  • 骨架屏：搜索与加载时用灰块占位，不要留白
  • 空状态：配引导文案和示例按钮，不要只有「暂无数据」
  • 智能体思考态：解析时逐条显示「正在理解需求 → 正在检索房源」，比一个转圈更能体现智能体在干活，演示效果好
  • 移动端：卡片单列，抽屉改全屏，筛选器收进底部弹层
图片素材怎么解决

房源图片是最大的缺口，建议走免费图库：Unsplash 或 Pexels 搜 apartment interior，下载 20–30 张放进 server/static/houses/，seed 时随机分配。合规、快、观感够用，页脚注明来源即可。另两个方案——纯色块占位观感差，找同学拍实景工作量太大。

09分工建议

五个人按端切分而不是按层切分——每人独立负责一条完整链路，不用互相等，也方便老师看清各自贡献。

负责人范围涉及
A租客端交易链签约、租约、账单缴费（T-04／05／06）
B房东端工作台、房源管理、预约处理（L-01～L-04）
C管理员端看板、审核、用户管理（M-01～M-03）
D智能体AI-03 客服、AI-02 合同审阅、对话记忆
E视觉与公共组件图片、首页主视觉、卡片改版、图表组件
每条链路都要自己写测试

沿用现有约定：纯函数写单元测试，接口写接口测试，都不依赖网络与大模型。提交前跑通 python -m unittest discover -s tests。目前已有 176 个测试，新增功能要把这个数字继续推上去——10 月 19 日测试周写《黑盒测试书》时，这些是现成的素材。
