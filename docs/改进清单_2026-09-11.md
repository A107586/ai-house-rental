## G1 的现状与方向

现在的分流是**三层关键词表**：`supervisor.classify` 一层、
`support_router._rule_service` 一层、各工具里的 `ASPECTS` / `REFERS` 又一层。
本轮 A1–A6 六个 bug 里有四个源自这个结构——**表总有漏的，
而漏了的后果不是「答得不好」，是「掉进另一条完全无关的路」**：
「看看第六套」掉进找房、「评价怎么样」掉进推销词。

方向是把「选哪条路」交给模型的工具调用（function calling）：
把每个能力登记成一个带 JSON Schema 的工具，模型只负责挑工具、填参数，
执行仍由代码做。关键约束不变：

- **金额、评分、房源字段一律由代码从库里取**，不经模型改写；
- **写操作仍走两阶段**：模型只能提议，用户点确认才执行；
- 模型不可用时退回现有规则链路——这条链路调了很久，是可靠的兜底，
  不能拆。
